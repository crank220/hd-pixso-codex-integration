# 精修与交付

先读取现有组件和用户手工调整，复用其设计系统；不要把某次示例尺寸强套到全部项目。

## 每层检查

- 同层级容器：对齐左右边界、区块标题与内容起点；统一内边距、圆角和分隔线。
- 表单：同类字段等高；双列宽度 + 列间距 = 整行可用宽度；边框不能偷走内容宽度。字段标签位置固定，文本垂直居中，错误信息不覆盖下一行。
- 导航和列表：图标占位、文字起点、尾部数量/操作对齐；选中背景与实际选中图层一一对应。新增页面行后同步下移图层行、高亮、折叠按钮和分隔线。
- 工具栏：图标视觉中心与点击区中心重合；工具状态改变后其颜色、背景、边框、光标和对应属性同步变化。真实内容与状态稿均可编辑。
- 弹窗：同类型弹窗采用一致宽度、标题栏、左右边距、底部按钮宽度/间距；Esc、聚焦限制、关闭后焦点恢复按规范标注。
- 同类状态：不要只改主界面而遗漏克隆的状态稿；读取各状态后分别核对，不通过全局替换破坏业务内容。
- 产品画面：不混入教学文案、实现细节或验收文本；必要业务空态和错误反馈属于产品内容，不能一概删除。

可使用 `pixso_audit` 的 `checks` 验证明确的同组规则：

```json
{"scopeToken":"...","checks":[
 {"nodeIds":["1:3","1:4"],"property":"width","tolerance":0},
 {"nodeIds":["1:3","1:4"],"property":"height","tolerance":0},
 {"nodeIds":["1:3","1:4"],"property":"y","tolerance":1}
]}
```

`x/y` 比较同父容器中的相对坐标；跨父容器时检查工具会报告需人工核对，不误报对齐通过。隐形层不当作可见缺陷；裁剪背景等合理溢出须结合截图判断。自动检查不理解全部业务语义，不能证明“每一处完美”。

截图审查至少覆盖主界面、需求涉及的每个工具/页面状态、弹窗及异常状态。只在新改动或未解决问题需要时重复检查。已存在可运行原型时测试实际悬停、按下、移出保留选中、切换工具和属性同步；没有可运行原型时说明交付的是设计状态，不能伪造操作验证。

## 按钮与溢出提示的实际含义

按钮复用核对真实组件来源/变体与适用端，再读回尺寸、内边距、文字和图标中心；同名或相似外观不等于复用成功。不把单次设备按钮64px、24px字号或标注数量当全项目标准。

对overflow逐类解释：布尔图形子层坐标、旋转图标、隐藏层、字形边界、背景裁剪与真实内容出界。结合祖先可见性、父层裁剪、坐标语义及最新截图判定；修正真实裁切/遮挡，保留无视觉缺陷的继承组件。记录原始提示数量、处理和人工接受依据，不把“已核查合理边界”写成“自动零提示”。
