# 产品画面与公司标注

读取用户指定的「UI/UX设计标注系统」后使用其真实规则；本文件不包含公司内部规范副本，也不替代读取证据。

## 分类与范围

产品画面只呈现最终产品：保留业务内容、页面名称、字段、操作和必要反馈；教学、开发说明、规则卡与验收清单放在产品画板外。不要误删真实业务文案。

根据交付规模组织产品场景、共用组件与状态、控件差异、核心流程；小任务可沿用旧页，复杂任务可在获授权文件内新增分类页面。用户只授权一个页面时才限定单页；新增页面不能扩展到其他设计文件。当前 MCP 仅支持已存在页面/子树的范围编辑，创建页面、移动分区需通过 Pixso 原生界面，再重新读取并绑定；不通过其他 MCP 绕过范围保护。

## 公共规则与逐控件差异

- 先盘点组件、实际实例关系和业务控件。完整、真实复用的组件可引用其共用规范；同名或外观相似不算真实复用。
- 公共颜色、间距、焦点、图标状态只定义一次。逐控件标明适用状态及引用位置，记录触发、提交、取消、校验、异常和权限的差异；不反复绘制相同状态条或复制通用说明。
- 自定义控件不能只写「同上」：须覆盖自身不同状态样式及交互；不适用的状态说明原因，异步反馈和选中状态不得混淆。
- 编号在约定范围内唯一；图中标记与对应说明一一对应。分类共用组件编号与业务控件编号使用不同前缀，引用须能定位，删除或合并说明后同步索引。
- 使用规范要求的颜色、编号、标题、责任人与日期。常见为蓝色交互、橙色内容、紫色状态、红色跨模块流程；以实际读取版本为准。连线指向真实对象，不能只指向无关说明卡。

## 原生注释与验收

分别记录：可编辑视觉图层、Pixso 原生注释、协作评论、原型连线、可运行逻辑。原生注释不等于协作评论，不向任意 pluginData 写入文字冒充原生能力。

先检查当前工具 schema 和官方能力。没有原生注释写接口时，可用获授权的 Pixso 原生界面：选择目标控件或模块，使用「添加注释」，填写并按公司规范分类。网页端可作为桌面操作不可用时的备选。操作前核对文件、页面和实际选中对象；不要固定假设某版 API、快捷键、菜单或 DOM 永远存在。

注释用于精炼说明设计决策与业务规则，不作为页面导航、操作教程或交付索引。仅在理解或实现存在歧义时添加，直接挂在相关对象上；不为凑齐数量逐模块批量生成，也不机械地给每个控件拆成蓝、橙、紫三条。

通常用一至三句写清本处关键信息：触发及结果、影响结果的约束或阈值、必要的异常和权限。按实际需要取舍，不罗列所有状态、不扩写常识，不重复控件标签或画面已表达的内容。必要业务信息不能为了短而省略。示例：「点击导出后生成文件；长边超过8192px禁止导出并提示，失败保留参数，可重试。」

共用样式与完整状态稿集中维护；注释只写该处差异，除确有必要的依赖外不加入“前往某页”“查看某编号”等指引。规范要求分类或编号时保留必要标识，但不以引用代替关键规则本身。

用户手动删除的注释属于最新设计状态，保留删除结果；后续改稿不自动恢复。用户再次明确要求添加时，重新读取现状，按上述原则精简编写。

保存后离开编辑态、重新打开并读回文本、分类、目标关联；更换视口或刷新后仍可读取才确认持久化。检查编号唯一、图中定位、内容覆盖和实际截图；输入动作成功不等于保存成功。能力或权限不足时，保留已完成结果并明确缺项，不声称完全合规。
