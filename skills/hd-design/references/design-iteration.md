# 真实需求迭代与完成验收

## 先盘点，再确定本次增量

真实需求迭代先只读查看设计文件中已有的页面，不限于固定期数。盘点已有功能、组件、风格、交互、管理入口与异常状态，再确定本次增量；无需调整项优先保留和复用，避免重复设计或丢失原管理功能。读取当前页面树和最新 revision，不从旧截图推断现状。

记录需求条目与已有场景的对应关系，区分新增、调整和沿用；这是任务验收记录，不放进产品界面。概要、明细、附件或历史说明冲突时，整理会影响范围的具体选项并与用户确认；已确认的决定持续有效，不重复询问。先推进不依赖答案的只读盘点。

## 页面分类、落笔与授权

- 多端需求按每个实际涉及的端分别组织页面，每页再分类主流程、状态与差异场景；不把多个端混成一个页面，也不为单端任务强行补齐其他端。
- hd-design 新增的页面名称须包含一次 `「hd-design」`，保留业务名称，例如 `三期-数字人-Web端「hd-design」`；本技能新增的分组也采用同一落笔，如 `三期「hd-design」`。标识放在设计页面/分组名称，不在产品画面内添加水印或说明。
- 仅修改用户指定的页面。新增页面必须在已授权的文件和工作范围内；需要修改其他页面时，先列出具体页面和原因并取得用户确认。删除页面必须单独与用户确认，不能把改稿、整理或整体任务授权视为删除确认；本轮对明确列出的具体删除已确认时无需重复问。
- 不给既有历史页面批量补落笔，不改共享主组件影响其他页面。页面改名后按页面 ID 核对身份，使用新名称重新绑定范围。

## 真实复用与控件检查

先按[项目识别与团队规范](xiaohuiyun.md)决定组件和风格来源。按钮不能只凭外观或名称认定复用：读回真实组件身份、变体、状态、文字/图标属性、宽高、内边距和中心对齐，并检查克隆出的各个状态稿。继承控件未调整时保留原功能和视觉。

图标优先复用已有图标或团队库实例；确无可用项时制作风格一致的可编辑图标，统一线宽、尺寸、视觉重量和状态颜色。具体状态规则见[图标状态](icon-states.md)。源库已连接、插件目录可检索、真实实例已导入是不同证据，目录未索引不能推断源库不存在。

## 标注与几何验收

所有项目均须读取并使用「UI/UX设计标注系统」标注。按[标注参考](annotations.md)分别验收视觉标记与说明、Pixso 原生注释、评论、原型和运行逻辑；原生注释输入成功不等于保存成功，需重开并刷新核对文本、实际分类和对象关联。

标记与说明按约定范围逐一对应；标记避开按钮文字、关闭入口和关键内容，标题与正文保留间距，窄区正文随内容增高并检查完整显示。数量由歧义与业务差异决定，不为达到历史案例数量而新增。

自动 overflow 提示逐类核对：布尔图形子层坐标、旋转图标、隐藏层、字体字形边界、背景裁剪和真实内容溢出。结合祖先可见性、坐标语义、clipsContent 与最新截图判断；修复真实裁切或遮挡，不为清零改坏继承组件。保留原始提示数量与解释，不把人工接受的合理边界写成“自动检查零问题”。

## 全部完成后结束

按确认的需求和端逐项检查设计、状态、组件来源、标注、保存、读回与截图；已通过的检查仅在新改动、失败或未解问题需要时重跑。阶段性完成只作进度，不作为最终完成。实际阻塞或需要用户支持时，先完成独立可推进的工作，明确缺项、所需支持与原因，再请用户确认。

最终说明具体位置、变化、验证及实际限制。静态状态稿不称为可运行产品；示意图片/二维码不称为真实业务资产。技能同步、插件发布、安装启用和运行版本分别验收；插件维护见[维护流程](plugin-maintenance.md)。
